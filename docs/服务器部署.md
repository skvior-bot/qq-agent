# 服务器部署（把三件套搬到一台常开的机器上）

> 本文是"要**一直在线**"时的做法：选机器 → 带什么过去 → 常开与自愈 → 远程访问 → 备份 → 升级。
> 不负责：装起来的最短路径 → `docs\安装.md`；仓库里哪个路径是什么 → `docs\仓库导览.md`。
> ★ 一句话：**家里那台和服务器上的差别，不在"能不能跑"，而在"谁看着它"** —— 桌面那套窗口/面板工具在服务器上基本没用，换成"任务计划或服务 ＋ 每天一次自检推消息"。

## 0. 结论先说：Windows 与 Linux **都能跑**
- **QQ 网关**：上游明确支持 Windows x64 / Linux x64 / arm64。★ **Linux 上官方只推 Docker 路线**（镜像里把 QQ、虚拟显示、远程桌面都封好了，扫码走浏览器里的远程桌面）；Windows 是本机手动路线。
- **DSH 本体 / 桥接**：两边都能跑（都是 Node；平台相关代码各只有一两处）。
- ★ **真正的成本在"桌面脚本"**：`tools\` 里那批 PowerShell 有一部分是**窗口管理**（服务器形态本来就不需要），启动链那几个在 Linux 上由 systemd ＋ docker compose 取代（**不是逐行翻译**）。
- ★ **"无头扫码"不是死路**：官方 Docker 镜像就是用"浏览器里的远程桌面"扫码的。

"服务器"其实有四种选择，都能满足"一直运行"：

| 选项 | 适合谁 | 代价 |
| --- | --- | --- |
| **家里旧 PC / 迷你主机**（最省事） | 有闲置机器；住宅 IP 登录 QQ **更不容易触发风控** | 断电、系统更新重启要自己处理 |
| **Windows VPS** | 想要真正的 7×24 ＋ 独立公网 IP | 月租；**新 IP 登录 QQ 可能触发验证**；CPU/显存弱 ⇒ 画图变慢；"没人登录桌面时 QQ 能不能起来"要按你的环境实测 |
| **Linux VPS（Docker）** | 想少维护：`restart: unless-stopped` ＋ 官方镜像 | 要会一点 docker compose；内存留 **≥ 2 GB**；`tools\*.ps1` 那套桌面工具用不上 |
| 就让当前这台常开 | 只是不想每次手动启动 | 你一关机它就离线 |

## 1. 目标形态：三件套，谁都不能停

| 组件 | 端口 | 缺了会怎样 |
| --- | --- | --- |
| **QQ 网关** | WS ＋ OneBot HTTP ＋ 管理页 | QQ 直接离线：群里看到"她不说话" |
| **桥接** | 控制台 | QQ 在线但**没人转达**：消息进来也不会有回应 |
| **DSH Web** | Web 界面 | 桥接建不了会话，她的工具调用全部失败 |

依赖方向：`QQ ↔ 网关 ↔ 桥接 ↔ DSH Web`。
★ **桥接必须和 DSH 在同一台机器**（它靠 DSH 的启动日志自动发现启动令牌）；网关也在同机（走回环地址）。

## 2. 迁移：从旧机器带什么过去

**必须带**：
- 桥接的 `config.json`（令牌、白名单、限额、全部配置）—— **含密钥，别进 git**。
- ★ **QQ 客户端自己的数据目录** —— **真正的登录态在这里**；而网关的 `data\<号>\` 只是**消息/媒体/身份缓存**，带过去**不能免扫码**（这条我们核实过，别搞反）。
- 网关的 OneBot 配置文件 —— ★ **HTTP 与 WS 两端的令牌必须同一个值**，否则 WS 握手反复失败。
- 桥接的 `state\` —— 会话状态、她的记忆、留言板工作区、限流计数（整目录带；临时目录可不带）。
- 画图 / 语音转写共用的**凭据文件**。
- 人设卡与 preset 源（它们在仓库里，但要在新机器跑一次 DSH 端安装脚本）。

**不能带 / 要在新机器重做**：
- 网关管理页的"免密登录凭据"：它在 Windows 上是**绑当前用户**的加密数据 ⇒ **换机器（或换 Linux）一律解不开**。
  → 新 Windows 机器：重存一次密码。→ **服务器上可以整条不要**：管理页本来就要走隧道，在隧道里手输一次即可。
- DSH 的模型凭据（在新机器重配一次）。
- 面板窗口状态（服务器上不需要面板，别带）。

⚠ **同一个 QQ 号不能同时在两台机器上登**：迁移时**先把旧机器的网关停掉**，再在新机器启动 —— 否则两边互挤下线（表现为反复掉线）。

## 3. 在新机器上从零跑起来

1. **装环境**：Node ≥ 22 ＋ Git。
2. **装 DSH CLI**：`npm i -g @deepseek-ai/dsh`。
3. **取代码**：clone 上游桥接仓库；把网关目录放到同级（它不在仓库里）。
4. **装依赖 ＋ 配置**：在桥接目录 `npm install`，然后照着 `config.example.json` 填一份 `config.json`（令牌与白名单）。
   ★ 若你**直接拷旧机器的** `config.json`，这一步可以跳过。
5. **装 DSH 端**：`node scripts\setup-dsh.mjs`（装 preset ＋ 挂工具 ＋ 注册控制台插件；细节与排错看上游文档）。
6. **首次登录 QQ**：起网关 → 打开本机管理页 → 扫码登录。
7. **起三件套**：★ **服务器上别用那个"一键启动"批处理** —— 它会重启 DSH、还会弹三个浏览器面板，那是给桌面看的。⇒ 按 §4 用任务计划/服务分别拉起。
8. **验收**：`node tools\self-check.mjs --deep` 全绿；再在 QQ 里发一句，看她是否回。

## 4. 常开与自愈（部署的重点）

- **桥接**：用**它自带的守护启动方式**（进程退出后会自动重新拉起），别直接 `node src\bridge.js`。
- **网关**：用它自带的启动方式；★ 它**不自带崩溃重启**，要外层守护。
- **DSH Web**：`dsh web --no-open`（别让它自己开浏览器）。★ **它的标准输出必须接进日志管道** —— 桥接靠那份日志发现启动令牌，**别把输出丢掉**。
- **开机自启**（选一条）：
  - **任务计划**（用户级即可）：触发器＝开机 ＋ 登录；动作＝最小化启动各组件的脚本；勾上"失败则每 1 分钟重启，最多 3 次"。
  - **做成服务**（NSSM / WinSW）：更省心，但★ 要**显式设工作目录与环境变量**，否则相对路径会错。
- **看门狗**：`tools\daily-check.mjs` **每天一次**自检，**只在发现问题时**给你推 QQ，且每次都往日志里落一行。
- **机器层面三条**（最容易忽略）：① 禁用睡眠/休眠；② 设好系统更新的活动时间（避免半夜自动重启）；③ ★ **别从 agent 会话里起常驻进程** —— 那种进程会随作业结束被回收，症状是"启动成功但几秒后消失"。

## 5. 远程访问：别把这三个端口裸奔

- 三个端口**默认只绑回环地址**，这是对的：一个的令牌会走 URL、一个的令牌在前端用、一个能改网关配置。
- 推荐：**远程桌面**进服务器（最省事）；或 Tailscale / ZeroTier 这类组网；或 **SSH 隧道**：
  ```
  ssh -L 3080:127.0.0.1:3080 -L 3100:127.0.0.1:3100 -L 5099:127.0.0.1:5099 <你的用户>@<你的服务器>
  ```
- **不要**把这三个端口直接映射到公网（没有 TLS、令牌可能被中间人拿走、管理页能被改配置）。
- QQ 侧是**出站长连接**，**不需要任何入站端口**。

## 6. 备份与恢复

- **要备的**：桥接配置、桥接状态目录、网关的数据与配置、凭据文件。
- **别进 git**：上面这些含令牌/密钥 —— 仓库的 `.gitignore` 已经把它们排掉了。
- **建议**：每天打包到**另一台机器 / 网盘**；只放本机备份**只防手滑、不防盘坏**。
- **恢复**：装环境 → 放回上述文件 → 跑一次 DSH 端安装脚本 → 起三件套 → `self-check --deep` 验收。

## 7. 升级流程（照这个顺序，别跳）

| 改了什么 | 要做什么 |
| --- | --- |
| 只改 `config.json` | 桥接大多**动态读**，多数立刻生效 |
| 改桥接源码 | **重启桥接**（用它的优雅重启脚本） |
| 改挂给 DSH 的工具脚本 | **必须重启 DSH**（只在进程启动时读一次，不热更） |
| 改 preset 的 YAML | 重跑 DSH 端安装脚本，新会话生效；改 preset 里的插件脚本则要重启 DSH |
| 改 PowerShell 脚本 | 文件必须保持 **UTF-8 带 BOM**（旧版 PowerShell 按 ANSI 读 ⇒ 中文乱码、直接解析失败） |

**标准升级动作**：`git pull` → `npm install`（依赖有变时）→ 跑 DSH 端安装脚本（preset/工具有变时）→ 重启 DSH → 优雅重启桥接 → `node tools\self-check.mjs --deep` 验收。

## 8. 一页 checklist

- [ ] 机器能常开，电源计划**已禁用睡眠**
- [ ] Node ≥ 22 装好，`dsh` 在 PATH 里
- [ ] 仓库 clone 好、网关目录放到位、依赖装过
- [ ] `config.json` 就位（令牌 / 白名单），旧机器的 `state\` 已带过来
- [ ] 登录态就位（带过来了，或已扫码），两端令牌一致
- [ ] DSH 端安装脚本跑过
- [ ] 三件套能从任务计划/服务起来，DSH 的输出接进了日志管道
- [ ] `node tools\self-check.mjs --deep` **0 失败**
- [ ] QQ 里发一句、她回话（端到端验收）
- [ ] 每天的自检任务已注册，日志里能看到它跑过
- [ ] 远程访问走隧道/远程桌面，**三个端口没暴露公网**
- [ ] 备份任务就位，且**验证过一次恢复**（只备份、没验过 = 没备份）
