# 架构与设计（这套东西怎么搭起来的、为什么这么搭）

> **本文负责**：整体形态 · 一条消息的旅程 · 关键取舍 · 会话 / 权限 / 成本三层的**做法**；★ 只讲"**为什么这么做**"，通篇不写地址、账号与内部台账（机制见 §5.4）。
> **不负责**（各自有专门一份）：路径 → `docs\仓库导览.md` ｜ 安装 → `docs\安装.md` ｜ 脚本 → `docs\工具一览.md` ｜ 省钱与踩坑 → `docs\省词元与稳定性.md` ｜ 服务器 → `docs\服务器部署.md`。

## 0. 一句话

**qq-agent = 一个 QQ 入口 ＋ 一个总控制开关。** 你在 QQ 里跟一个 agent 说话，它在**你自己那台机器上真的动手**，再把结果回到 QQ；浏览器那边照常有完整界面 —— **两个入口是同一个 agent、同一套对话、同一份权限**。

★ **产品前提：得有一个"一直开着的点"**（一台不关机的机器）—— 只在你坐下来聊天时才开机，那还不如直接开浏览器：**24 小时在线是前提，不是选项**（→ `docs\服务器部署.md`）。

**两条判据**：① 新用户要理解几个概念、记几个地址、按几个键？目标 **0 / 0 / 1**；② **任何时刻界面上都要有一句"你现在该做什么"**（§3.7）。

## 1. 整体形态：四层，每层只干一件事

```
QQ 群 / 私聊（真人）
   │ QQ 协议
   ▼
① QQ 网关      ← 第三方：QQ 协议 ↔ 通用接口（本仓库不含它）
   ▼
② 桥接         ← 第三方开源项目（本仓库是改过的副本）：翻译一问一答、白名单、分条发送
   ▼
③ agent 运行时 ← 上游安装包 ＋ 本工作区 preset（角色卡、工具挂载）：调模型、跑工具
   ▼
④ 模型服务     ← 上游服务，用你自己的账号与额度
```

| 层 | 归谁 · 它的边界 |
| --- | --- |
| QQ 网关 | 第三方 · 只管协议翻译 |
| 桥接 | 第三方（改过的副本）· 只管"聊天消息 ↔ agent 的一轮" |
| agent 运行时 | 本工作区 ＋ 上游 · 决定"这一轮做什么"，**工具是唯一的动手方式** |
| 模型服务 | 上游 · 决定"怎么想"，拿不到你的文件 |

**为什么切成四层**：每层都能**单独替换、单独指认**（换网关或换模型，别层一字不用改）。★ **代价**：四个单点 ⇒ 启动器管的是**这四个的启动顺序与自愈**（§3.1）。

**控制面只有一个**：启动 / 停止 / 重启 / 看状态 / 看日志，无论从命令行、网页还是 QQ 里按，都落到**同一份动作白名单**。★ 本项目反复长出来的毛病就一个形状 —— **同一个动作有两份实现**。

## 2. 一条消息的完整旅程

| # | 发生了什么 | 边界 / 取舍 |
| --- | --- | --- |
| ① | 网关收到 QQ 消息，转成事件推给桥接 | 全走本机连接，不对公网开口 |
| ② | 桥接判断"这条要不要理" | 白名单 ＋ 唤醒条件（被 @ / 叫名字 / 关键词）——**默认"潜水"** |
| ③ | 消息被投进某一条**对话** | 同一个 QQ 会话 → 同一条对话；**已归档的拒绝投递**（§3.5） |
| ④ | agent 干活：模型决定调工具，工具回灌结果，可能来回几轮 | **唯一**的动手方式（工具白名单枚举）；写操作受沙箱约束或要人批准 |
| ⑤ | 回复：**回合结束才发**（不流式），长回复**分条**、按真人节奏给间隔 | 分条为了像人说话；间隔为了不刷屏 |
| ⑥ | 留痕：本地日志 ＋ 结构化账本 | 排障与成本都从这层长出来（§6） |

**两个"看起来多余、其实必须有"的动作**：**投递 = 发 ＋ 核实**（**核实过**才叫送达）；**每轮先读上下文再说话**（不靠记忆猜）。

★ 反方向也有一条**单向**的路（agent 主动推消息，例如"要不要批准"）：只"送到"，不负责叫醒对方。

## 3. 关键取舍

### 3.1 "隐藏窗口"的正解是**不创建窗口**

**取舍**：藏别人的窗口 ↔ 根本不创建。**为什么**：扫荡式的自动动作一定误伤（早先的"守窗器"把使用者自己的窗口一起藏了）⇒ 铁律：**自动动作只作用在自己创建的对象上**。**做法**：无关组件以**后台进程**跑、输出走文件重定向；★ **判据是"窗口对象不存在"，不是"用了哪个 API"**。★ 后台化**必须连守护一起搬**（有前科：某组件跟着另一个重启一起死、没人拉回来）。

### 3.2 配置按"变化原因"分层

**取舍**：一份"什么都有"的大配置 ↔ 按**变化原因**分层。判据一句话：**换个人、换台机器，这个值会不会变？** ⇒ **环境层**（端口 / 路径 / 账号 / 白名单）· **业务层**（工具开关、限额、唤醒策略）· **凭证层**（**只引用不复制**，永不进对外副本）。**两条规矩**：① 缺字段 = 用默认值 **＋ 出声**（静默的默认值最难查）；② **不许一次性搬家**，**迁一项就删掉那一处的硬编码**；验收 = 改一个端口只改**一处** ＋ 自检加条**棘轮**（硬编码端口**只许变少**）。

### 3.3 模式按"谁在用"分，不按技术档位

三种模式：**① 省心（默认）**（只想在 QQ 里说话）—— **我们自己的一个浏览器窗口**（判据 = 窗口句柄，能真唤醒）；**② 开发**（常去界面调东西）—— 开进**你正在用的浏览器**，靠白名单，**检测失败只打印地址、绝不重开**；**③ 挂机**（服务器）—— 只开一页或**一页都不开**。

**为什么**：**浏览器会休眠后台标签** ⇒ "用连接 / 心跳推断页面在不在"这个判据**系统性失真**（重复开一份、醒来还是旧状态）。正解是**把判据换成我们真正能控制的对象**（自己拉起的窗口用句柄）；做不到的那一档就退化成"**绝不重开、只打印地址**"。

### 3.4 权限三级：**AI 不许自己给自己发权限**

| 级 | 谁做 | 范围 |
| --- | --- | --- |
| **L1 它自己可做** | QQ 侧的 agent | 记反馈、调**白名单内少量运行时配置**（唤醒概率、关键词一类）；**留痕、可回滚** |
| **L2 需人批准** | 人批准 → 由**另一个**开发方向的会话实现 | 进待办 → 实现 → 记账 |
| **L3 永不自改** | 谁都不许自动 | **代码、权限、白名单、凭证、工具挂载清单** |

**为什么**：**AI 改自己的代码 = 自己给自己发权限** —— 跑偏了没有任何东西拦得住 ⇒「自我迭代」**不等于**"自己改自己"，而是 **提建议 → 人批准 → 另一个人实现**（三层分离、留痕）。

### 3.5 归档 = **只读历史**（单向、不删、明着拒）

**取舍**：归档 = 删掉 / 藏起来 ↔ 归档 = **只读的历史记录**。**三条硬约定**：① **永不自动归档、永不删除**，只有人**显式触发**；② 任何"往对话里发消息"的通道，目标已归档就**拒绝**（fail-closed）且**拒绝要能被看见** —— **不许静默丢弃、也不许偷偷"复活"**；③ 归档**单向** ⇒ **不许按"可撤销"设计**；被归档的 QQ 会话由**新建一条**接住，钉死某条对话的绑定被归档 ⇒ **只记日志、绝不自动重建**。

**为什么**：一条还能被写入的历史，这个词就没有意义了；而"**看不见的拒绝**"是最坏的失败。★ 别拿"不在对话清单里"当归档判据（归档的对话**仍在**清单里），唯一真相源是**归档名单**，而且**每次读盘、不做时间戳缓存**。

### 3.6 第三方一律"不并入"

**取舍**：把第三方组件打进包里"开箱即用" ↔ 让使用者**自己去装**。**为什么**：① "未获书面授权就并入安装包 / 镜像"是明确被禁止的；② 自己装的还白赚一条：**拿到的是自己平台的原生包**。**做法**：对外副本**永不包含**第三方组件，**也绝不提供"自动下载并安装"的一键脚本**。

### 3.7 引导是功能，不是文案

**判据**：让**不懂技术的人**从零到"在 QQ 里收到回复"，**全程不问任何问题**。**做法**：① 界面任何时刻有一句"**下一动作**"且带**动作 id** —— **控制面只说"现在缺什么"，"怎么按"由载体自己渲染**（命令行说"按 r"、网页说"点启动"）；② 首启向导**只问必要的那个问题**，其余自动推断；需要使用者动手的地方**必须做成引导**。

## 4. 会话这一层

- **一条对话 = 一段上下文 ＋ 一个工作目录 ＋ 可归档的历史。** 上下文越长每步越贵（"地板"随长度线性上涨）→ `docs\省词元与稳定性.md`。
- **什么时候换新对话**：两个口径，都**从账本长出来、不拍脑袋** —— **步数**（1 步 = 1 次模型调用）与**花费**（按官方价折算）；**任意一条越线就触发**，各设两档。★ 只看步数会漏掉"**步数不多、但很贵**"的对话。
- **只提醒"人自己在界面上的对话"**：子任务、QQ 侧、空对话、已归档**一律排除**（越线的几乎全是这几类）。
- **人没回应：不升级、不重发、绝不自动归档**；正在跑的**延后**（归档了它，新对话还得重新接活）。**同一档只提醒一次、状态落盘**（删掉状态文件就会重发 —— 这正是"真读了盘"的证据）。

## 5. 权限与安全边界

**5.1 三层「谁能做什么」**：**谁能说话**（群 / 人白名单）· **能做什么**（工具是**白名单枚举**；禁言、踢人这类高危动作**默认关闭**）· **什么永不自动**（代码 / 权限 / 白名单 / 凭证 / 归档 —— §3.4 的 L3）。

**5.2 可观测性本身是安全设施**：四个组件各有状态灯 ⇒ "**哪一层不健康**"必须**可指认**。★ **"绿在不该绿的地方"比红更贵** —— 判据要能证明自己**真在这棵树上跑过**。

**5.3 fail-closed：读不到就别猜**：① 判不出忙不忙 ⇒ **当忙**；② 读不到归档名单 ⇒ **不提醒**（投递链不拦 —— 读失败不该让人掉线）；③ 读不到成本数据 ⇒ 只按步数判、**金额整段隐藏**（**不许把"读不到"当成 0**）。

**5.4 真值与对外副本**：副本是**派生产物** —— 从源码树复制、把真值换成可读占位（**源码一字不动**）。**硬闸**：副本里**身份真值必须 0 处**（非 0 拒交付），另有**独立对账**用别的算法再数一遍（取严）；**另一条闸**：副本里文档**引用的文档必须真在副本里**。

## 6. 成本这一层

成本是**一等设计约束**：同一个功能，写法不同能差一个数量级。三条事实（实测与复算脚本 → `docs\省词元与稳定性.md`）：① **单价由缓存命中率决定**；② **每一步都在付"上下文地板"**，地板随对话变长抬高；③ **压缩很贵**（一次约等于几十步普通调用）⇒ 阈值必须**高于压缩后的地板**。

**落到架构上**：**短对话优先**（干完一段就换新）；**重活派子任务**（只把**结论**带回主线）；**先定位再读**（**禁止整读**大文件）；**不给任何"定时叫醒"加闹钟**；**推理档位分级**（改生产代码 / 动成本口径 / 事故处置 / 对外交付用最高档，且**另开一条会话复核**）。★ 新功能**先报价**；预算低就**砍范围，不砍判据质量**。
