# 仓库导览（哪个路径是什么、什么时候才需要进去）

> 本文回答：**这份仓库里每个顶层路径是什么、什么时候才需要打开它**。
> 不负责：逐个脚本干什么 → `docs\工具一览.md`；怎么装起来 → `docs\安装.md`；为什么这么设计、钱花在哪 → `docs\省词元与稳定性.md`。
> ★ 一句话用法：**先看这张表决定"要不要进那个目录"，再打开对应文档** —— 别一上来把整棵树都读一遍（读得越多越贵，这条本身就是我们踩出来的）。

## 0. 先认清一件事：这份仓库**不带** QQ 桥接本体
消息进出 QQ 的那一层（桥接）是**别人的开源项目**，许可是他们的事 ⇒ **我们不替你分发**，你自己 clone 上游那份；
这份仓库里是**我们改过的那部分 ＋ 围绕它的整套工具与文档**。两处怎么接起来 → `CONTRIBUTING.md`（上游四条说明）与 `docs\安装.md`。

## 1. 顶层路径一览（这份仓库里真有的）

| 路径 | 是什么 | 什么时候才进 |
| --- | --- | --- |
| `README.md` | 一页鸟瞰：消息怎么走、哪些是本工作区的、已知限制 | 第一次拿到包时 |
| `CONTRIBUTING.md` | 想改这个仓库 / 自己搭一份时的入口（含"上游要先 clone"的四条） | 动手改之前 |
| `LICENSE` | MIT | 你要分发时看一眼 |
| `agent.config.example.json` | **环境层配置模板**（纯占位，照着填） | 装的时候 |
| `.gitattributes` | 行尾**写死**（`.cmd` / `.bat` = CRLF，其余 = LF）—— ★ **别删**：删了 Windows 批处理在别的机器上会坏 | 只在动行尾时 |
| `docs\安装.md` | 从零装起来（最短路径） | 装的时候 |
| `docs\工具一览.md` | `tools\` 里每个脚本干什么、什么时候跑 | 想跑脚本时 |
| `docs\仓库导览.md` | 本文 | 认路 |
| `docs\服务器部署.md` | 搬到一台常开的机器上跑：步骤与判据 | 要"一直在线"时 |
| `docs\省词元与稳定性.md` | 为什么这么设计：钱花在哪、压缩为什么贵、我们踩过的坑 | 想省成本、或出了怪事时 |
| `tools\` | **71 个脚本**一整套：自检、体检、打包、发布前扫描、安装、启动/关闭、面板、沙箱…（清单 → `docs\工具一览.md`） | 按 `docs\工具一览.md` 那张表挑一个跑 |

## 2. 这份仓库里**没有**、但要你自己准备的两处

| 你要什么 | 去哪儿拿 | 为什么不在包里 |
| --- | --- | --- |
| **QQ 桥接本体**（消息进出的那一层） | 上游 `qq-bridge`（GitHub 上那个开源项目） | 那是别人的项目、许可归他们 ⇒ 我们不分发 |
| **DSH 端的接线**（preset ＋ 工具挂载） | 同样在上游那份里：`qq-bridge\dsh\agent-presets\`、`qq-bridge\src\mcp-*.js` | 同上；装法见 `CONTRIBUTING.md` 与 `docs\安装.md` |

## 3. 三条"地图级"的别踩

- **`tools\self-check.mjs` 是只读体检**：装完 / 改完先跑它。★ 它绿 **≠** 能发出去 —— 能不能发由 `tools\scan-secrets.cjs` 说了算（两件事，见 `docs\工具一览.md` §1）。
- **行尾别手工改**：`.cmd` / `.bat` 必须 CRLF，其余 LF；仓库根的 `.gitattributes` 已经写死这条口径，绕过它手工改会在别人的机器上炸。
- **脚本一律在仓库根跑**：脚本自己会推导仓库根，**不用**先 `cd tools\`。
